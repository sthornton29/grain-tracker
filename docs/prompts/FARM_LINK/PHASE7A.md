# Turnrow Grain: Farm link prompt (Phase 7, Part A, run in ~/grain-tracker)

The Grain side of the link between Turnrow Farm and Turnrow Grain: a per-organization pairing, a private API that lets Turnrow Farm push entities, farms, fields, and plantings into Grain and pull production, marketing, income, and bins out of it, a settlements hand-off for landowner shares, and the rule that land records in a linked organization are managed in Turnrow Farm. Written 2026-09-17. Part B (the Farm side) runs afterwards in ~/turnrow-farm and depends on this being deployed first.

## 1. Read this first

You are working in Turnrow Grain (repo grain-tracker, local folder ~/grain-tracker). Read PROJECT_SUMMARY.md end to end first, then docs/PARTNER_API.md (the read-only landowner partner API: share codes, per-connection scopes, bearer tokens, service-role reads scoped by token, updated_at delta sync, the aliases key reserved on fields), the migrations that created organizations, organization_members, current_org_id(), the RESTRICTIVE isolation policies, super_admins, partner_shares and partner_api_tokens, and the CSV import engine (lib/csv.ts, lib/import-configs.ts) with its farms, fields, and plantings importers. Keep every Grain convention: migration numbering continues from the latest file; every new table carries org_id, updated_at, and the full RESTRICTIVE policy stack inline in the same migration and is added to the tenant table arrays the verify scripts read; nothing new is exposed to landowner partners unless this prompt says so; PROJECT_SUMMARY.md is regenerated at the end with the endpoints documented in a new docs/FARM_LINK_API.md.

Decisions on record: Turnrow Farm is the MASTER for entities, farms, fields, boundaries, and plantings; Grain is the master for loads, bins, contracts, hedging, settlements, yields, crop insurance, government payments, and marketing prices; the two will merge on desktop later and stay separate mobile apps. ## 2. Data model (one migration)

- farm_links: org_id, code_hash (a one-time pairing code with prefix "fl_", shown once, expires in 7 days if unredeemed), token_hash (the long-lived bearer token issued at redemption, prefix "flt_", rotatable), farm_org_id (Turnrow Farm's organization uuid, learned at handshake), farm_org_name, scopes text[] (land:write, production:read, marketing:read, income:read, bins:read, assumptions:write, settlements:write; all granted by default because both sides are the same organization; the owner can remove any), status (pending | active | revoked), created_by, redeemed_at, last_seen_at, last_sync jsonb. One active link per organization.
- farm_link_ids: org_id, grain_table (entities | farms | fields | field_plantings | field_planting_varieties | crops | landowners), grain_id, farm_uid (Turnrow Farm's uuid), linked_at, linked_by (handshake | match | sync). Unique (org_id, grain_table, grain_id) and unique (org_id, grain_table, farm_uid). This is the id map; no farm_uid columns on core tables.
- landowner_settlements: org_id, farm_uid (the Farm lease year id), landowner_name, landowner_farm_uid, crop_year, lease_type, statement jsonb (the statement rows exactly as Farm's lib/leases/statement.ts produces them: farms, fields, acres, crops, yields, prices, shares, cost shares, adjustments, payments, notes), finalized_at, received_at. Unique (org_id, farm_uid). Exposed to landowner partners only through a new share scope (section 5).
- A managed_by column on entities, farms, fields, and field_plantings: null | 'turnrow_farm'. Set on every row the link writes or matches; the UI treats managed rows as read-only (section 6).

## 3. Pairing and authentication

- /settings/farm-link (owner role): Generate pairing code (shown once with the instruction "paste this into Turnrow Farm under Settings > Integrations > Turnrow Grain"), the link status, the Farm organization name, scopes with toggles, last sync per direction, Rotate token, Revoke. A super admin sees links across organizations on /admin.
- POST /api/farm-link/v1/handshake {code, farm_org_id, farm_org_name}: verifies the code, issues the token, records the Farm organization, returns {token, grain_org_id, grain_org_name, scopes, api_version, base_urls}. Every other endpoint: Authorization Bearer flt_..., service-role queries scoped to the link's org_id, 401 on a revoked or unknown token, 403 on a missing scope, rate limited per link, every call logged with counts (a rolling table trimmed daily). Responses are JSON with updated_at on every record and cursor paging (limit, cursor) the way the partner API pages.

## 4. Endpoints

### 4.1 Land, inbound (scope land:write)

- GET /api/farm-link/v1/land/snapshot: everything Grain currently holds so Farm can match before it writes: entities (id, name, entity_role), landowners (id, name), farms (id, name, entity_id, farm_code, county name and state, landowner_id, is_share_rent, landlord_share_percentage, cash_rent_per_acre), fields (id, farm_id, name_or_number, total_acres, irrigated_acres, county), crops (id, name, harvest_category, double_crop), field_plantings for the requested season years (id, field_id, crop_id, season_year, planted_acres, planting_date, paired_planting_id, irrigated_acres, varieties), each with updated_at and the farm_uid from the id map when already linked.
- POST /api/farm-link/v1/land/link {links: [{grain_table, grain_id, farm_uid}]}: writes the id map for matches Farm confirmed after review; rejects a grain_id or farm_uid already mapped elsewhere.
- POST /api/farm-link/v1/land/sync {entities, landowners, farms, fields, crops, plantings, deletions}: idempotent upserts keyed on farm_uid through the id map (create when unmapped, update when mapped), in dependency order, inside one transaction per batch of up to 500 records: entities (name, entity_role); landowners (name); farms (name, entity, farm_code, county by name and state through Grain's counties table, landowner, the lease columns); fields (farm, name_or_number, total_acres, irrigated_acres, county); crops (create a per-organization crop when Farm sends a name Grain lacks, such as Sunflower, with harvest_category and double_crop from Farm); plantings (field, crop by name, season_year, planted_acres, planting_date, irrigated_acres, paired_planting_id resolved from the preceding planting's farm_uid, varieties replaced as a set). Deletions arrive as archive requests (Grain archives, never deletes, and refuses to archive a field or planting that has loads, yields, or settlements, returning the conflict). The response lists every record with its grain_id, action (created | updated | unchanged | conflict | refused), and the reason. Conflict rule: a Grain row whose updated_at is later than the last sync and whose managed_by is null (edited in Grain before the link) is returned as a conflict with Grain's values, never overwritten silently; once managed_by is set, Farm's values win. Every written row gets managed_by = 'turnrow_farm'.
- After a successful sync, Grain's own farms, fields, and plantings CSV importers refuse to run for that organization with the message "land records are managed in Turnrow Farm", and the forms for those tables render read-only with the same note and a link (section 6).

### 4.2 Production, marketing, income, bins, outbound

- GET /api/farm-link/v1/production?season_year=&since= (production:read): one record per field planting (and per entity when the agent flow-down applies): field farm_uid when mapped, grain ids, crop name, harvest_status (complete | in_progress | unharvested), harvested_acres, production (dry bushels for grains, lint pounds for cotton, with the unit), yield_per_acre, moisture where recorded, source (combine_yield_entries | loads | settlements, in Grain's precedence), updated_at. The same numbers Grain's own yields pages show; never a recomputation.
- GET /api/farm-link/v1/marketing?crop_year=&since= (marketing:read): per crop and per entity: settled_average_price (the tenant's average sale price with the unit and the count of settled bushels or pounds), projected_average_price with its basis (Grain's marketing dashboard figure), percent_sold, hedging_realized (gains and losses by crop, net), basis notes, updated_at. Cotton in cents per pound as Grain stores it, with the unit stated.
- GET /api/farm-link/v1/income?crop_year=&since= (income:read): per field planting where Grain attributes it and per crop and entity otherwise: crop_revenue (settlements net of the marketing fee and hedging where Grain applies them, with the components), government_payments (by program and FSA farm, the pro rata flow-down already applied), crop_insurance_indemnities, other_income, each with updated_at and Grain's attribution basis (by field, by acres, by production share).
- GET /api/farm-link/v1/bins?crop_year=&as_of= (bins:read): per bin and crop: bushels on hand, bushels in for the year, bin name and capacity.
- Every outbound record carries the Farm uuid from the id map when the field or planting is linked, so Farm needs no matching on the way back.

### 4.3 Assumptions and settlements, inbound

- POST /api/farm-link/v1/assumptions {crop_year, rows: [{crop, cost_per_acre, cost_per_acre_irrigated, cost_per_acre_dryland, cost_per_acre_dc_irrigated, cost_per_acre_dc_dryland, source, computed_at}]} (assumptions:write): updates crop_assumptions.cost_per_acre and its breakouts for the organization and crop year, and budget_lines.cost_per_acre where a budget scenario is marked to follow Farm; every touched row records source 'turnrow_farm' and the timestamp so the Grain UI shows "from Turnrow Farm, updated <date>" with a manual override switch.
- POST /api/farm-link/v1/settlements (settlements:write): upserts landowner_settlements by farm_uid (section 2).

## 5. Landowner partner shares: the settlements scope

Add a partner share scope "settlements" (default OFF, like projected price and projected yield) that exposes landowner_settlements for the landowner's mapped farms through the existing partner API (GET /api/partner/v1/settlements?crop_year=), the statement rows only for that landowner (matched by the landowner id the share is bound to and the landowner_farm_uid map), never another landowner's, never the tenant's costs beyond the cost-share categories the statement itself shows. Document it in docs/PARTNER_API.md and the "what the landowner sees" preview on /settings/shares. Turnrow Landowner consumes it in its own later prompt.

## 6. Grain UI for a linked organization

- /settings/farm-link shows the last sync per direction with counts and the conflicts Grain returned.
