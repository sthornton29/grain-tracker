| UI | **React `^18.3.1`**, **Tailwind CSS `^3.4.14`** (no theme extensions/plugins) |

| USDA data | **NASS Quick Stats API** (monthly MYA "prices received" — the primary lookup, `lib/nass-quickstats.ts`, free `NASS_API_KEY`) + **FSA ARC-CO benchmark workbook** downloaded and parsed server-side (`lib/fsa-benchmark-file.ts`, cached in the DB) + **RMA Price Discovery OData service** (064/065 — `lib/rma-price-discovery.ts` + `/api/rma-price-discovery`: projected/harvest insurance prices + volatility, STATE-keyed with per-state discovery windows AND the offer's own base contract from the CEPP-keyed data (AL corn = ZCU26 September, never the Midwest ZCZ/DEC assumption — the Barchart estimate tier quotes the offer's contract via `symbol_override`); statuses Yet To Start/In Discovery/Released; cached in `rma_price_cache` (global, lazy refresh — daily in-window, weekly idle; refresh is WRITE-THEN-SWAP: `mergeRmaResults` validates before replacing display state, failures keep prior values with an as-of error — never a blanked window; the route runs crop × state combos concurrently with 10s per-fetch timeouts), rows mirrored into `harvest_price_estimates` (`harvest_final` 'RMA final' / `harvest_estimate` 'rma_discovery' / `projected` 'RMA final' — always written; precedence lives in resolution). Projected tiering (`resolveProjectedPrice`, source-aware): RMA released > manual (notice + keep-mine; typing over a known RMA value auto-keeps) > seed (the 065-relabeled 024 nationals — demoted silently). No offer for a state → "No RMA offer", never blank. The ADM pipe-delimited Price dataset is the documented fallback source if the .svc endpoint ever churns |
| Market data | **Barchart OnDemand** REST (futures + options quotes) |
| Exports / files | `exceljs`, `xlsx` (SheetJS), `jspdf` + `jspdf-autotable`, `pdf-lib`, `jszip` |
| Testing / CI | **Vitest `^4.1.8`** — 1,450 unit tests: the pure `lib/` math (69 `lib/*.test.ts` files, incl. the help-coverage CI gate, the 077 `lib/seed-contracts.test.ts` suite, and `lib/variety-yields.test.ts` — variety attribution/conservation/share-weighted stats) plus the first jsdom component suite (`components/truck-picker.test.tsx` — the load form's inline truck rename; `@vitejs/plugin-react` + per-file jsdom pragma); ESLint (`.eslintrc.json`, `next/core-web-vitals`); **GitHub Actions CI** (`.github/workflows/ci.yml`: lint + test on every push/PR) |
| Packaging | **npm** (`package-lock.json`); installable **PWA** (service worker `/sw.js`, `manifest.json`) |

**Request flow:** `middleware.ts` → `lib/supabase/middleware.ts` refreshes the Supabase
session and redirects unauthenticated users to `/login` (public paths: `/login`,
`/auth/callback`). **Role guards** (`lib/route-guard.ts`, the pure role → path matrix): `gin`
users are server-side-redirected to `/cotton/loads` from every non-cotton path; `viewer`
users (052 — read-only stakeholders) are redirected to `/reports` from everything except
`/`, `/yields`, `/reports/*`, `/logout`, and the read-only price-lookup APIs the reports
call; `agronomist` users (061 — org-wide production advisors) are redirected to `/yields`
from everything except `/yields/*` and `/logout` (help is open to every role). The nav
hides everything else and the 042/052/061 RLS policies enforce underneath. The
root layout (`app/layout.tsx`) renders the top `<Nav>` only when
signed in, plus `<PwaRegister>`.

**Data access:** Pages mostly read/write Supabase **directly** from server or client
components. The server-side API routes are for AI parsing, market-price fetching, and the
**read-only partner API** under `/api/partner/v1/*` (bearer `PARTNER_API_TOKEN`, service-role
reads — see §5). Heavy report math lives in `lib/` (pure functions) and `components/reports/`.

**No views in the database** — all reporting is computed in the app layer. The money-critical
pure logic in `lib/` is covered by Vitest unit tests (`npm run test`); UI components are not.

## 2. Pages — every route and what it does

### Navigation structure

The global nav (`components/nav.tsx`, sticky forest-green bar with the white mark + TURNROW wordmark) and the landing tiles (`app/page.tsx`) BOTH render from **`lib/nav-links.ts`** (`navLinksFor` — single source of truth, so they cannot drift; gin role → Cotton only; viewer role → Yields + Reports only; agronomist role → Yields only). 9 top-level destinations:
New Load, Loads, Bin Inventory, Contracts, Settlements, Yields, Hedging, Reports, Settings —
plus a single **Cotton** tab (inserted right after Hedging) when the **Cotton module** is
enabled (`app_settings.cotton_module_enabled`, toggled under Settings → Users & Modules).
The three cotton pages live in a **Reports-style left sidebar** (`app/cotton/layout.tsx`) —
the old green sub-nav bar is gone. **Gin-role** users see ONLY the Cotton tab (the sidebar
inside gives them the three intake pages).
The home page (`app/page.tsx`) is a tile launcher: **New Load** renders as the page's one
solid-kelly primary action bar (only for roles whose link set includes it), and the remaining
links are quiet white cards — hairline border, Montserrat label, and a small "turnrow tick" in
the module's wayfinding hue (`NavLink.tick`, a static class in `lib/nav-links.ts`) that extends
on hover; the Ask Turnrow strip is the same card species with a kelly tick (landing-only,
never a nav tab). There are **three layouts**: the root
(auth + nav + PWA), `app/reports/layout.tsx`, and `app/cotton/layout.tsx` (left sidebars). The Reports navigation —
group order, item order, display names, routes, descriptions — has a **single source of truth**
in `app/reports/reports-nav.ts`; both the sidebar and the landing-page cards render from it.
Groups: **Main Reports / Crop Insurance / Production Reports / Government Payments /
Operational Reports**. Items marked `external` point back to standalone pages with a ↗ marker.
**Viewer role**: `reportGroupsFor(role)` filters both the sidebar and the landing cards through
the `lib/route-guard.ts` matrix — viewers lose the ↗ operational links (Loads, Contracts,
Inventory…) and the two whole-operation reports with no entity dimension (**Settlement PDFs**,
**Crop Budget**); empty groups drop out.

> Most report subpages are thin `'use client'` wrappers that render a heavy component from
> `components/reports/*` and wire an `<ExportBar>` (Excel/PDF/Print). All reports share a
> **design-system kit** (`components/reports/report-kit.tsx`): header/filter bar/summary
> cards/tables/empty states, number formatters, and color-tone semantics (green favorable,
> red unfavorable, amber warning). Detail pages handle missing records with `notFound()`.
> There are **no** `loading.tsx`/`error.tsx`/`not-found.tsx` files.
>
> **Printing** is a single shared `@media print` stylesheet in `app/globals.css` (it hides
> nav/sidebar/`.no-print`/form controls, flows the body with `break-inside: avoid` on cards
> and rows, repeats table headers, and forces `print-color-adjust: exact` so green/red/amber
> survive). A print-only `<PrintHeader>` (reports layout) stamps the generation date and the
> SIGNED-IN ORG's own name (fetched from their organization — never hardcoded; every
> customer's printouts carry their farm's name); report
> titles print. The browser **Print** button alone now yields the full formatted document —
> the earlier `body:has(.print-area)` isolation rule blanked the page and was removed.

## 3. Database schema

**Supabase / PostgreSQL** with `pgcrypto` (`gen_random_uuid()`). Defined by **76 sequential,
idempotent migrations** in `supabase/` (`schema.sql` = 001, then `002_*.sql` … `076_*.sql`).
Every table re-runs safely (`create table if not exists`, guarded `do $$…$$`), uses a `uuid`
PK and `created_at`. ~80 tables, **no views**. Later migrations frequently `ALTER` earlier
tables (esp. `contracts`, `farms`, `fields`, `field_plantings`, `crop_assumptions`,
`crop_insurance_policies`). `035` adds the irrigated/dryland **practice** column to
`crop_insurance_policies` (default `non_irrigated`); a policy is now keyed by entity ×
crop × county × crop_year × practice (+ plan_type), SCO/ECO inherit it. `036` adds
`covers_all_planted_acres` (default false) + `coverage_note` to `crop_insurance_policies` — the
Coverage Check attestation that suppresses acre-mismatch flags for a combination.

### Tables (grouped) — purpose & key columns

**Org & land**

- **`entities`** — legal entities (LLCs/partnerships). `name` (unique), `notes`, **`payment_limit_persons`** (041 — FSA eligible persons, entity-level: total ARC/PLC limit = persons × the program year's per-person limit), **`entity_role`** (051 — `farming` default / `marketing_agent`: agent-held contracts/hedges flow down pro-rata in the entity-filtered reports).

- **Shrink math** (`lib/shrink.ts`) — net weight + moisture + crop base values → wet & dry bushels; honors `dry_bushels_override`; falls back to wet bushels when moisture is missing.
- **Yield analysis** (`lib/yields.ts`) — aggregates dry bushels per field/crop/year, drops unharvested fields, and flags a partially-harvested field as "in progress" under two rules. **(1) The active field is never complete (2026-09-02)**: while the crop is active, a field with loads but NO later-dated load from any other field of the crop (same crop year) is the one the combine is in — `in_progress` regardless of yield, even a normal one — "later" is by date, then by `loads.time` on the same day when both fields' newest loads carry a time (`FieldCropAgg.lastLoadTime` / `YieldInput.lastLoadTime`, fetched by every classifier consumer — the 2026-09-02 Moore/Wheeler Grove fix: a mid-afternoon field switch no longer holds the earlier field); a same-day tie with a time missing holds both; the hold clears when a later-dated load lands on another field (moved on → rule 2 decides) OR the crop goes quiet past the window (for the trailing field of the season its own last load IS the crop's last load, so the two formulations coincide). "Count anyway", the combine-entry `harvest_complete`, and the crop-level flag still complete a field from any state. **(2) The persistent low-yield rule**: LOW YIELD (>15% below the baseline, `IN_PROGRESS_THRESHOLD`) is the primary signal and it PERSISTS — a later-dated load on ANOTHER field is NOT completion evidence (operators start a field, move off, and come back). A low field leaves in-progress only via the explicit "count anyway" override, the combine-entry/crop-level harvest-complete flag, or **CROP-WIDE** silence: >10 **calendar** days (`IN_PROGRESS_STALE_DAYS`) with no loads for the crop ANYWHERE in the analyzed scope — never merely its own loads stopping (calendar-date math so the window never shortens by the local time of day). **Baseline hierarchy** (2026-08-26): with ≥`IN_PROGRESS_MIN_PEERS` (2) other harvested fields → their weighted average, preferring the *resting* ones (own loads quiet past the window) so one partial field can't shelter another; with thinner peers → the planting's **expected yield** from crop_assumptions (`expectedYieldForPlanting` — per-practice irr/dry where broken out, acre-weighted for mixed), so the crop's FIRST field classifies correctly instead of defaulting complete (the old no-peers hole); with neither → complete, reported in `YieldAnalysis.noBaseline` and shown in the Yields drill-down ("nothing to compare against yet"). A field at/above the bar is complete as usual once the combine has moved on (rule 1 no longer holds it); `noBaseline` is now reachable only when a peer can't form a baseline (zero-acre peers) — a lone recent field is held by rule 1 instead of defaulting complete; a genuinely-finished-terrible field (crop failure) is indistinguishable from an abandoned partial — "count anyway" is the documented path. Every consumer passes assumptions (yields page, landowner/season/insurance/income-sensitivity reports, marketing seams, assistant, partner API), so classification is identical on every surface; produces weighted averages and harvest-progress-by-acres. `harvestStatusOf` / `isHarvestComplete` classify a planting (complete / in-progress / unharvested) to gate the bushel-allocation and variety-prompt UI; `cropsWithCompleteHarvest` feeds the Marketing dashboard's actual-vs-estimated switch, and `inProgressPlantingsByCrop` names the holdout fields so the Marketing dashboard and the Crop Insurance report can offer the same persisted "Count anyway" override in place. `groupYieldAggregates` rolls the harvest-included plantings up by group × crop × season (same irr/dry breakdown rules as By Farm) — powers the **Yields By Entity** tab and is generic enough for any grouping.

- **Marketing engine** (`lib/marketing.ts`) — per-crop position for a crop year: acres segmented full-season/double-crop × irr/dry, expected production from assumption breakouts (or **actual production once harvest is complete**), a Total Average Price buildup (weighted futures from physical contracts + open short hedges, realized futures/options P&L spread per bushel, and a **bushel-weighted basis blend** — locked contracts at their weighted basis, the rest at the assumed basis), and a **blended expected revenue** that values each bushel bucket (flat-cash, futures+basis, open-hedge, and completely-unpriced at the **assumed futures price** when set else the harvest-price estimate, + assumed basis) at its own price. Blended revenue is the **single source of truth** for `revenuePerAcre`/`profitPerAcre`/`totalProfit` (so the dashboard and Revenue Projections agree) and is **capped at `totalProduction`** — contracts beyond expected production (over-contracting, e.g. canola sold on a higher yield) scale down so revenue can't be booked for grain you won't grow. ### AI document parsing pipeline

All AI extraction funnels through **one route** — `POST /api/parse-document` (`maxDuration
300` — the Fluid-compute ceiling on every Vercel plan; if a deploy rejects it, drop to 60 —
chunking is the real fix) — called only via `parseDocument(input, documentType)` in
`lib/pdf-upload.ts`. A PDF is uploaded to the `documents` bucket and sent to Claude **by
https URL** (to stay under Vercel's 4.5 MB serverless body limit; the temp object is deleted
after parsing). Photos are inlined as base64 `images[]`; `.xlsx/.xls` are rendered to PDF
first (`lib/excel-to-pdf.ts`).

**EVERY upload surface parses through `parseDocumentChunked` (`lib/parse-chunked.ts`)** — the
platform-wide 504 fix: long PDFs AND photo batches split into page batches (`lib/pdf-split.ts`;
default 6 pages, the four pre-existing batched importers keep 4), one serverless call per
batch, progress labels ("Reading pages 9–16 of 24…"), **one automatic retry per chunk**, and
partial-failure reporting (successful chunks are KEPT; the caller shows "Pages 12–15 couldn't
be read — try uploading those pages separately", never a bare 504). Per-doc-type merge
functions in **`lib/parse-merge.ts`** (pure, tested in `lib/parse-merge.test.ts`) dedupe
records straddling chunk boundaries — tickets/settlement lines by ticket number, cotton loads
by load number, bales/PBIs by the digits-no-leading-zeros rule, settings records via
`mergeSettingsExtractions`, exact-JSON repeats otherwise — and take header/scalar fields from
the first non-null chunk (page 1). Single-chunk documents behave exactly like the old direct
call, including error identity (`PdfTooLargeError`).

The route selects one of **13 hard-coded prompts** by `document_type` (the cotton marketing
type additionally carries **7 focused category sub-prompts** and accepts an optional `category`
for a re-extract), sends document blocks +
a text prompt as a single message, strips markdown fences, and `JSON.parse`s the result.
**No tool use and no structured-output schema enforcement** — prompts say "respond ONLY in
JSON" and parsing is defensive (a malformed response → 500 "Couldn't parse the response").

Extracted rows are fuzzy-matched (`lib/fuzzy.ts`) to existing reference data and land in an
**editable review table** — nothing is written to Supabase until the user presses "Save All".

- **Multi-tenant traps (053/054)** — new tenant tables must add `org_id` (NOT NULL, the coalesce(current_org_id, default_org_id) default, `(org_id)` index) AND the `_org_isolation` restrictive policy, and appear in the tenant lists in 053, 054, `verify_053.sql`, and `verify_054.sql`; new unique constraints on natural keys must include `org_id` (FK-keyed uniques are fine). Storage uploads must go through `uploadFileToStorage` (org-prefixed) and deletes through `deleteStorageObject`. Remaining cutover debts: per-org-ify `cotton_fee_schedule`/`arc_plc_price_data` (+ their upserts), flip `app_role()` to organization_members, private storage bucket + signed URLs, an org-management UI (orgs are created by hand + `seed_org_defaults`).

### Conventions / gotchas

- **Single-entity auto-assign — ONE seam** (`lib/entity-default.ts` `defaultEntityId(entities)`: exactly one entity → its id, else null; pure over the passed list so the answer flips the moment a second entity exists — never cache it). Every DATA-ENTRY entity picker renders `components/entity-select.tsx` `<EntitySelect>` (hidden by default; `showWhenSingle` = disabled+pre-filled where seeing the entity aids confidence — contracts, insurance policies, cotton sales/loans, statement-import account entity; it only auto-fills an EMPTY value so edit forms keep the record's stored entity). CSV entity columns pass `fk.fallbackId: defaultEntityId(entities)` (blank cell or absent column resolves to it; csv-import treats required-with-fallback as satisfied — no star, import unblocked; sync blanks never overwrite); AI/doc imports resolve via `resolveUploadEntityId` (chosen → single-entity auto → fallback → null), which delegates to the seam. Report/list entity dropdowns are FILTERS, not data entry — they keep their own behavior. Statement-import's possibly-closed comparison spans null-entity legacy positions in a single-entity org (`entityScopeMatches`). When adding any new entity input, use these seams — no inline `entities.length === 1` ternaries.

## 8. Domain glossary

- **Shrink / dry bushels / wet bushels** — wet = net weight ÷ test weight; dry = wet shrunk to the crop's base moisture. Shrink removes water weight above base so grain prices at a common moisture.
- **Base moisture / base lb-per-bushel** — per-crop FSA standards (e.g. corn 15% / 56 lb).
- **Practice (irrigated / dryland)** — whether acres are irrigated; tracked per field/planting and reported separately (esp. crop insurance).
- **Double-crop** — a second crop after a spring-harvest crop in the same season (e.g. soybeans after wheat).
- **FSA number** — USDA Farm Service Agency farm serial number.
- **APH yield** — Actual Production History; approved per-acre yield setting insurance guarantees.
- **RP / RP-HPE / YP** — Revenue Protection, RP with Harvest Price Exclusion, Yield Protection.
- **Coverage level / unit structure** — % of guarantee insured; enterprise / basic / optional acre grouping.
- **SCO / ECO** — Supplemental / Enhanced Coverage Option: county-based band endorsements above the base policy.
- **Projected / harvest price** — RMA's spring and harvest futures-based prices valuing the guarantee/indemnity.
- **Indemnity / premium** — the insurance payout / the producer-paid cost of coverage.
- **My-yield-vs-county differential** — the operator-entered amount their own yields run ABOVE the county average, in the crop's own unit (bu/ac, lbs/ac); estimated county yield = the farm's own yield basis − differential. Drives every county-triggered insurance leg (047).
- **ARC / PLC** — USDA Title I: Agriculture Risk Coverage (county/individual) and Price Loss Coverage; elected per farm × commodity.
- **Base acres / PLC yield** — program acreage and payment yield a farm carries (independent of what's planted); unassigned/generic base carries no payment.
- **MYA price** — Marketing-Year Average price; drives PLC and ARC.
- **Reference price / loan rate** — statutory PLC price floor and the national loan rate that floors the MYA.
- **Payment factor / sequestration** — the 85% base-acre payment factor and ~5.4% federal sequestration cut on ARC/PLC.
- **Forward / HTA / Basis contract** — forward locks flat cash; HTA locks futures (basis later); basis locks basis (futures later). `cash = futures + basis − fee`.
- **Basis** — local cash minus futures (positive = "over", negative = "under"). **Assumed basis / assumed futures** — per-crop-year standing assumptions (`crop_assumptions.assumed_basis` / `assumed_futures`) used to value the crop's unlocked / unpriced bushels, so Total Average Price always computes; both are edited in the dashboard's What-If block and cleared together via "Clear assumptions".
- **Hedging (long / short)** — offsetting futures/options; farmers typically short futures to lock a price.
- **Realized / unrealized P&L** — closed-position profit/loss vs mark-to-market on open positions.
- **Settlement / settlement line** — the buyer's payment document; lines match delivered loads by **ticket number** (gross − discounts = net).
- **Scale ticket / ticket number** — the per-load weigh-in document; the join key between loads and settlement lines.
- **Crop year vs season year** — `crop_year` (marketing/program year on loads/contracts) vs `season_year` (planting season); usually aligned, tracked separately.
